08 · Eliminating Prefix-Breaking Anti-Patterns ​

1 · Start2 · Qualify & Size3 · Design4 · Validate5 · Govern
4 min readVerified 2026-11-18 21:21 PST
Why It Matters

One dynamic character—like a timestamp or unsorted JSON key—in the first 1,024 tokens silently forces 0% cache hits across all calls.

Key Takeaway

Strip timestamps and user IDs from Pos 1–3, sort tools[] and JSON keys deterministically, keep response_format static, and push RAG chunks to Pos 6.

Practical Application

Compare the Before vs. After visual and Python code snippet below directly against context-assembly middleware during Week 1/2.

A single dynamic byte inside the first 1,024 tokens forces cached_tokens = 0 and, on GPT-5.6+ Standard or GPT-6+ PTU-M, writes a new unamortized cache entry [M]. Below are the six prefix-breaking patterns most frequently uncovered during codebase audits.

Six Middleware & Tooling Anti-Patterns [Arch] ​

Anti-PatternWhy It Breaks Caching in the Agent RuntimeRequired Engineering Fix
1. Early request-context timestamp & user ID injectionMiddleware prepending request_timestamp: "2026-11-18T21:21:00Z" or user_id at the top of system mutates the prefix around token ~40 on every call.Keep Positions 1–3 100% user- and time-agnostic. Place scoped L2/L1 cards at Positions 4–5, and pass timestamps in Position 6 only when date reasoning is needed.
2. Non-deterministic tools[] schema serializationBuilding an agent's toolset from an unordered set/dict or dynamic MCP discovery changes tool order or JSON key order across container replicas.Sort tools by tool["function"]["name"] (or Responses tool["name"]) and canonicalize schemas with json.dumps(..., sort_keys=True) at startup.
3. Dynamic response_format schema mutationsAzure OpenAI prepends the structured output schema before the system message [M]. Mutating enum lists or field descriptions per request invalidates token 0.Keep response_format schemas static per node/skill version; pass dynamic allowed codes in Position 6 instead of mutating the JSON schema.
4. Prepending RAG passages ahead of instructionsPrompt templates placing retrieved search chunks at the top ("Given these documents...") invalidate everything after token 0 on every query.Move static role, policy, rubric rules, and few-shot examples to Positions 1–3; inject retrieved RAG passages inside the final user turn (Position 6).
5. Sliding-window front truncation & unbounded all_turns reasoningDropping turn 1 when turn 6 arrives shifts every subsequent token offset; meanwhile gpt-5.6/6 default reasoning.context to all_turns [M], inflating multi-turn input tokens.Keep history append-only within a session window; set reasoning.context: "current_turn" when cross-turn reasoning replay is unnecessary, and compact via periodic checkpoints.
6. Per-turn tool filtering ahead of static contextAdding/removing tools dynamically on every turn mutates Position 2, invalidating Position 3 static reference blocks that follow.Keep a stable toolset per skill/node family (and route distinct skills to separate prompt_cache_key prefixes).

Middleware Refactoring Pattern (Before vs. After) ​

python
import json

# ❌ ANTI-PATTERN: Injecting live timestamp & user_id at the top of the system prompt
def build_messages_broken(req_ctx: dict, static_policy: str, domain_methodology: str, rag_chunks: str, query: str):
    # Token ~15 mutates on EVERY call because req_ctx["timestamp"] is a live ISO timestamp!
    sys_text = f"<session_context>{json.dumps(req_ctx)}</session_context>\n{static_policy}\n{domain_methodology}"
    return [{"role": "system", "content": sys_text}, {"role": "user", "content": f"{rag_chunks}\n{query}"}]


# ✅ CACHE-READY PATTERN: Keep system + tools[] 100% Global T0 (Pos 1-3); place L2/L1 after tools[] (Pos 4-5)
def build_messages_cache_ready(
    static_policy: str,
    domain_methodology: str,
    l2_workspace_card: dict,
    l1_persona_card: dict,
    history: list[dict],
    rag_chunks: str,
    query: str,
    supports_explicit_breakpoints: bool,  # True on Standard 5.6+ & PTU-M GPT-6+; False on PTU-M GPT-5.6
):
    t0_block = {"type": "text", "text": f"{static_policy}\n\n{domain_methodology}"}      # Pos 1 & 3 (Global T0 >= 1,024t)
    l2_block = {"type": "text", "text": json.dumps(l2_workspace_card, sort_keys=True)}   # Pos 4 (shared per scope_id)
    l1_block = {"type": "text", "text": json.dumps(l1_persona_card, sort_keys=True)}     # Pos 5a (shared per user_id)

    if supports_explicit_breakpoints:
        t0_block["prompt_cache_breakpoint"] = {"mode": "explicit"}  # Breakpoint #1: global T0 + tools[] reuse
        l2_block["prompt_cache_breakpoint"] = {"mode": "explicit"}  # Breakpoint #2: workspace-wide L2 reuse

    return [
        {"role": "system", "content": [t0_block]},       # Rendered with sorted tools[] ahead of conversation messages
        {"role": "developer", "content": [l2_block, l1_block]},  # Pos 4-5a: scoped context after Global T0 + tools[]
        *history,                                        # Pos 5b: append-only checkpointed turns
        {"role": "user", "content": f"<retrieved_grounding>\n{rag_chunks}\n</retrieved_grounding>\n\n{query}"},  # Pos 6
    ]

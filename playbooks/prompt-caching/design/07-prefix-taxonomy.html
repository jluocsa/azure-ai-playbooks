07 · Scope × Volatility Prefix Architecture ​

1 · Start2 · Qualify & Size3 · Design4 · Validate5 · Govern
4 min readVerified 2026-11-18 21:21 PST
Why It Matters

Mixing global instructions, workspace metadata, session history, and live RAG chunks in arbitrary order destroys cross-user and cross-turn cache hits.

Key Takeaway

Order every prompt strictly from most-shared & static (Pos 1–3 Global T0) to workspace-scoped (Pos 4 L2), session-scoped (Pos 5 L1), and live RAG last (Pos 6).

Practical Application

Use the Pos 1–6 diagram below during design reviews to map every prompt block onto its exact scope and volatility position.

Enterprise agent context divides cleanly along two orthogonal axes [Arch]:

  • Axis A — Scope: Global (all users & workspaces) → Workspace / Case (scope_id) → User / Thread (user_id, thread_id).
  • Axis B — Volatility: Static Release (T0) → Low/Medium Scoped Card (L2 / L1) → Always-Live RAG & MCP Tail.

Mapping those two axes onto Prompt Positions 1–6 maximizes KV-cache reuse across both concurrent users and multi-turn sessions.

Context Precedence Without Breaking the Prefix

Declare static precedence instructions ("Workspace scope L2 governs domain constraints; User L1 governs output formatting") in Position 1, while keeping the actual L2 and L1 payloads in Positions 4 and 5. For strict client/matter ethical walls—including Posture A Zero-Client-Cache Mode (explicit mode with Breakpoint #1 on T0 only, writing zero client tokens to KV cache)—see Regulated Multi-Engagement & Compliance Platforms.
